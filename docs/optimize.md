# Optimize PDF (lossless)

Choose **Alat → Optimize PDF (lossless)** and a new `.pdf` destination. Optimize
captures all current workspace pages, including imports, reorder, rotations and
deletions. Thumbnail selection does not restrict the operation. Source PDFs and
existing destinations are never overwritten.

The result notice shows before/after sizes, exact bytes and the percentage decrease
or increase. A valid result is kept even if it is unchanged or larger. There is no
fixed reduction promise and no quality slider, downsampling or JPEG re-encoding.

## What the size comparison means

Before optimization is a standard QPDF export of the same captured page plan,
created inside the owned staging directory. It is not the sum of imported files,
and it does not count deleted pages as compression savings. QPDF then optimizes
this staged baseline; the after size is the validated file that gets committed.
Only the final PDF is published. The temporary baseline and job files are cleaned.

Optimize is a derived export: it does not mark edits saved or change history,
selection or source references. Use **Simpan sebagai** to establish a saved PDF
workspace revision. Editing can continue after the snapshot is captured. Open/Close
waits for an active Optimize and then checks unsaved changes again.

## Compression and document policy

Pinned QPDF 12.4.2 receives a separate JSON job with `objectStreams=generate`,
`streamData=compress`, `recompressFlate` and `compressionLevel=9`. These optimize
object/stream storage without rasterizing pages or enabling lossy image optimization.
Object streams may raise the PDF version to 1.5. No new dependency/sidecar is added.

Lossless describes page content/image compression, not universal preservation of
every document-level feature. Optimize uses the conservative full Save As preflight:
unsupported forms, signatures, encryption, tagged restructuring, active content and
other complex structures remain blocked. Supported bookmark/Info/XMP omission needs
the existing explicit consent. Source files remain intact and viewing is independent
of export support. The whole-source Selected Extract exception is not an Optimize
compatibility bypass. See ADR-0003 and compatibility.md.

## Transactions and limits

The immutable plan uses `ExportScope::Optimized`; its receipt cannot advance the
clean baseline. `OptimizationSizes` reports the staged baseline and output byte
counts. Sizes are read through the output transaction port before publication,
keeping filesystem I/O outside the UI/domain. Zero-size artifacts fail validation.

Private source snapshots, clean QPDF checks, PDFium page count/geometry/orientation
validation, source rechecks, flushing and no-clobber publication follow the existing
pipeline. Cancel/failure removes owned staging and publishes no partial destination.
The normal per-window export slot, phase progress and **Batal ekspor** are reused.

Existing 1024-page/128 MiB source bounds, 16 MiB QPDF JSON bounds and cumulative
120-second QPDF child-process budget remain. Level-9 recompression can take time;
size reduction is not guaranteed. PDFium validation stays in-process and cooperatively
cancellable, without a hard native timeout. Crash recovery, overwrite, portable
release certification and broad complex-document fidelity remain separate work.

## Verification

Run `scripts/check.ps1`, `scripts/smoke-test.ps1` and
`scripts/optimize-ui-smoke.ps1 -Profile release`. For fresh UI fixtures, first run
`cargo run --locked -p pdf-smoke -- --write-export-fixtures`.

Native checks compare optimized pages with an ordinary export of the identical
plan: exact 512px RGBA, extracted text, mixed-source order/rotation and exact byte
sizes. Synthetic scan/JPEG/blank-page cases are included; the original encoded JPEG
bytes must remain present in the optimized PDF. The tiny JPEG is generated by
`scripts/new-optimize-fixture.ps1`, with no external image/user document. Tests also
cover loss consent/blockers, source changes, no-clobber races and cancellation/failure
after writing. Unit tests explicitly accept smaller/equal/larger outputs and reject
empty artifacts. See testing.md for actual executions and UI evidence.
